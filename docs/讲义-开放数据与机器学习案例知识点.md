## 1. 开放数据获取：CKAN API 与许可

### 1.1 数据目录 vs 数据本体

avoindata.suomi.fi 是基于 **CKAN**（开源数据目录平台）的国家门户。关键区分：

- **数据目录**：告诉我"有什么数据集、谁发布的、什么格式、更新频率、许可"——通过 CKAN Action API 查询。
- **数据本体**：真正的 CSV/JSON/SHP 文件，往往在另一个 URL 上，目录只存元数据和下载链接。

教学上，这正是「大数据时代首先要会找数据、看清条款再用」的演练。

### 1.2 CKAN Action API 四个端点

```
GET /data/fi/api/3/action/package_search?q=bicycle       # 搜数据集
GET /data/fi/api/3/action/package_show?id=<name>          # 元数据 + 资源列表
GET /data/fi/api/3/action/group_list                      # 14 个主题分类
GET /data/fi/api/3/action/organization_list               # 759 家发布机构
```

注意路径必须带语言段 `/data/fi/`（或 `/data/en_GB/`），裸 `/api/` 返回 404。

### 1.3 开放许可

avoindata 上绝大多数数据是 **CC BY 4.0** 或 **CC0**：

- `CC BY 4.0`：注明出处即可商用、修改、再发布。
- `CC0`：放弃著作权，可无条件使用。

教学中要反复强调：新闻作品、学生作业、竞赛作品里用第三方数据，许可和署名义务必须核对——"能下到"不等于"能用"。

## 2. 数据清洗：真实脏数据的典型坑

### 2.1 共享单车 CSV 里的脏点

- **UTF-8 BOM**：文件头多了 `\ufeff`，字段名被污染。`pandas.read_csv` 用 `utf-8-sig` 或容忍即可。
- **时间格式不统一**：个别行 `Departure` 只有 `2024-06-13` 没有时分秒，直接 `%Y-%m-%dT%H:%M:%S` 解析会崩。`pd.to_datetime(..., format="ISO8601", errors="coerce")` 宽容解析后再 `dropna`——这就是"先能跑，再讨论怎么处理"的工程哲学。
- **非正/超界值**：距离 < 0 或 > 30 km、时长 < 0 或 > 180 min 的记录大概率是传感器故障或忘还车，按业务逻辑过滤。
- **编码混杂**：事故 CSV 是分号分隔 + Latin-1 编码，不是 UTF-8。

### 2.2 清洗流程的三层

```
原始 46.9 万条
  → 层1 格式/编码/时间解析：丢弃格式不完整的行
  → 层2 业务规则：非正、超界值剔除（约 2.9%）
  → 层3 特征衍生：距离 m→km、时长 s→min、小时、星期
  → 有效 45.5 万条
```

每层都打印过滤数量，让学生看见"清洗不是一次性魔法，是可审计的步骤"。

### 2.3 数据质量与最终结论的对应关系

- 剔除 3 小时以上行程 → "中位时长 11.8 分钟"这个结论才代表正常骑行，否则长尾污染中位数。
- 过滤超 30 km → Top 站点排名才可靠，否则极少数异常点可能扭曲聚合。

## 3. 描述统计与聚合分析

### 3.1 中位数 vs 均值：右偏分布的经典例子

- 距离中位数 2.14 km，均值 2.78 km —— 均值被少数长行程拉高。
- 时长中位数 11.8 min，均值 16.3 min —— 同样是长尾。

这正是"什么时候该报中位数"的最佳演示：收入、房价、行程时长、点击时长，绝大多数现实世界指标都是右偏。

### 3.2 groupby 的三种形态

```python
df.groupby(df["dep_time"].dt.hour).size()        # 按小时 → 双峰通勤曲线
df.groupby(df["dep_time"].dt.date).size()        # 按日期 → 逐日趋势
pd.concat([df.dep_station, df.ret_station]).value_counts()  # 按站点 → Top N
```

三种 groupby 输出三种完全不同形态的可视化：曲线、时间序列、排序条形图——让学生体会"同一个数据，不同聚合维度讲不同故事"。

### 3.3 比值类指标：借还同站率

`(df.dep_station == df.ret_station).mean()` = 4.3%。这个比值本身简单，但它支撑了一个业务判断："赫尔辛基共享单车主要是点对点通勤，不是休闲绕圈"——教学生**从比例读出业务含义**，不是只算数。

## 5. 机器学习基础：LIBSVM 稀疏格式与 TF-IDF

### 5.1 LIBSVM/SVMlight 稀疏格式

```
label1,label2,...  feat1:weight1 feat2:weight2 ...
```

- **为什么要稀疏**：文本 TF-IDF 后每行实际非零维度可能只有几十到几百个，但特征空间是 28 万到 58 万维。如果按 dense 存，每行 58 万 × 8 字节 ≈ 4.6MB，3.1 万行就是 143GB——稀疏格式只存非零值，把空间压到每行几百字节。
- **首部头行**：`3150 580408 35999` = 标签数、特征数、样本数。真实数据集的惯例，脚本要跳过。
- **和 CSV 的对比**：CSV 是"每行一个完整记录"，LIBSVM 是"每行一组非零索引"——讲数据格式如何反映任务特性。

### 5.2 TF-IDF

- **TF**：词在当前文档出现频率，越高说明越相关。
- **IDF**：词在所有文档出现的倒数，越罕见区分度越高。
- **公式**：$tfidf(w, d) = tf(w,d) \times \log\frac{N}{df(w)}$

图书馆员语料是官方预切好的 TF-IDF；中文演示是自己用 `jieba.lcut` 分词 + `TfidfVectorizer` 现算的——**两种来源对比，正好讲"特征工程在不同项目里谁来做"**。

## 6. 多标签分类：OvR、precision@k、长尾

### 6.1 为什么不能直接当单标签

图书馆员数据每个问题平均挂 4.6 个标签，3150 个主题空间。如果强行当单标签做（取最主要的标签），就丢了"一封咨询同时涉及借阅规则+数据库使用+版权边界"的真实情况。

### 6.2 OneVsRest（OvR）

核心思路：把多标签问题拆成 N 个二分类问题——对每个标签单独训练一个"是/不是"分类器，预测时每个标签独立打分。

```
OvR: 3150 个 LogisticRegression 二分类器，共享一份特征
预测: 每个标签给一个概率 → 按概率排序取 Top-k
```

教学点：OvR 是最直观的多标签扩展，但代价是模型数量 = 标签数——3150 个逻辑回归在 28 万特征上就是 9 亿参数，直接 OOM。

### 6.3 标签长尾与演示降级

真实数据里 3150 个标签中，前 100 个覆盖了大多数样本。演示把标签空间压到 Top-100，否则：

- 训练内存：3150 × 280k 特征 ≈ 爆
- 评估噪音：稀疏标签只有几个样本，precision@k 不可信

这是"数据规模 vs 教学可行性"的取舍——课堂上能跑通的演示比"全量但内存炸"有用。

### 6.4 precision@k

```
pred = 模型对每个标签的概率排序，取前 k 个
precision@k = 每个样本命中的标签数 / min(k, 真实标签数)，再对样本取平均
```

和普通 precision 的区别：**不看阈值，看排序**——多标签任务里"前 5 个预测中几个对"比"0.5 概率切线是否预测正类"更符合人类评估习惯。图书馆员基线 precision@1 ≈ 0.51、precision@5 ≈ 0.49。

### 6.5 真实踩过的坑（案例卡里写明了）

- 官方 train/test 文件用了 TNPP 和 Voikko 两种芬兰语分词器，特征维度不一致——**跨文件评估直接错位**，改用单文件本地 80/20 切分。
- `load_svmlight_file` 不读 StringIO，只读文件路径——写个临时文件给它。
- sklearn ≥1.2 不再接受 list-of-lists 多标签，必须 `MultiLabelBinarizer` 转成 binary indicator 矩阵。

## 7. 类别不均衡：准确率陷阱与召回率

### 7.1 严重/轻微事故 = 3.7:1

- 84.7% 准确率，乍看不错。
- 但少数类（轻微）召回只有 50.7%——意思是 1134 条真实轻微事故被误判成严重。

### 7.2 混淆矩阵怎么读

```
真实严重 → 预测严重 8060   预测轻微 538   ← 误报（严重事故漏判）
真实轻微 → 预测严重 1134   预测轻微 1167  ← 漏报（轻微事故误报为严重）
```

业务含义：漏报严重事故 = 该派人抢救的没去；误报 = 虚惊。哪个代价大取决于任务——**讲清楚"评估指标必须和业务代价挂钩"**，别只背 precision/recall 定义。

### 7.3 几种调整手段（讲原理，不要求全部实现）

- `class_weight="balanced"`：给少数类更高权重。
- 阈值移动：把概率切线从 0.5 往下移，抓更多少数类。
- SMOTE/过采样：合成少数类样本。
- `sample_weight`：逐样本加权。

### 7.4 树模型 vs 线性模型

- `HistGradientBoostingClassifier`：对稀疏/非线性友好，50 万行内快。
- `LogisticRegression`：系数图直观可读（哪个方向是严重/轻微），但只能学线性边界。

对比着讲：**树模型胜在非线性，线性模型胜在可解释**——这是"选模型先看任务"的实用判断。

## 8. 中文多标签：分词、伪标签、Dash 实时预测

### 8.1 中文分词的特殊性

英文按空格分，芬兰语按词形还原（Voikko/TNPP）分——**语言决定特征工程**。

中文演示用 `jieba.lcut` 分词，接 `TfidfVectorizer(tokenizer=..., token_pattern=None)`：
- `token_pattern=None` 必须显式关掉默认正则，否则 jieba 输出的词会被二次清洗。
- `max_features=40000` 控制词汇量，避免内存膨胀。

### 8.2 伪多标签构造：类别质心相似度

```
对每类 c: centroid_c = 该类所有标题 TF-IDF 均值向量
对每条样本 i:
    own = 真实标签
    extra = 与 i 余弦相似度最高的 (除 own 外) Top-2 类别
    labels_i = own ∪ extra
```

教学点：真实中文多标签语料极难找，**用 TF-IDF + 类别质心补伪标签**是模拟"一稿多栏目"的可行工程方案——前提是要讲清楚"这是构造的，不是人工标注的"。

### 8.3 稀疏矩阵不能 `.toarray()`

```
30000 × 40000 float64 = 8.94 GB → OOM
正确做法：X.multiply(X).sum(axis=1) 行归一化，保持稀疏
```

这是"数据规模 ≠ 不能算"的典型示范：30k×40k 稀疏矩阵用 sparse 乘法只要几百 MB，dense 化就爆。

### 8.4 Dash 实时预测的完整链路

```
Input 输入框 (debounce=True)
    ↓ Input.value 触发 callback
    ↓ jieba.lcut(输入文本)
    ↓ vec.transform(文本) → TF-IDF 向量
    ↓ clf.predict_proba(X) → 15 类概率
    ↓ np.argsort(-proba)[:8] → Top8
    ↓ plotly Bar(orientation='h') → 概率条
    ↓ 前端 re-render
```

对比 avoindata 看板（KPI + 地图 + 曲线），中文看板是**单输入单输出的最小交互**——正好讲"一个输入框 + 一个模型 + 一个图，就是一个最小可用产品"。

## 10. 工程经验：真实演示里踩过的坑

| 坑 | 场景 | 解法 |
|---|---|---|
| `toarray()` 转 dense OOM | 30k×40k 稀疏矩阵 | `X.multiply` 行归一化，保持稀疏 |
| OvR n_jobs=4 pickle 失败 | 并行训练中文分类 | 转 `n_jobs=1`，30k 也只要 40 秒 |
| 3150 标签 OvR OOM | 图书馆员全量 | 压到 Top-100 标签子集 |
| train/test 特征空间不一致 | 图书馆员官方文件 | 单文件本地切分 |
| `n_jobs` 和 loky 序列化问题 | sklearn 并行 | 单线程跑通比并行挂了强 |
| 文件头 BOM / 分号分隔 / Latin-1 | 各处 CSV | `utf-8-sig` / `sep` / `encoding` 参数 |
| 时间列只有日期无时分秒 | 共享单车 CSV | `format="ISO8601", errors="coerce"` |
| `lru_cache` 必要性 | Dash 双回调并发 | 同月份只解析一次 CSV |

**这些坑本身就是教学点**——学生在自己项目里会遇到一模一样的问题，演示代码里留注释就是"经验写在代码里"。

## 11. 延伸阅读与练习

- 换月份对比：同一代码跑 5 月 vs 8 月，看通勤模式是否稳定。
- 特征工程：把"时段"（早高峰/平峰/晚高峰/夜间）做成离散特征看对分类的影响。
- 阈值扫描：事故分类从 0.3 到 0.7 扫 precision/recall，找代价平衡点。
- 跨数据集：把图书馆员的 `load_sparse` 改成中文 TF-IDF → LIBSVM 的导出，复用 OvR 管线。
- 对比模型：`LinearSVC(class_weight="balanced")` vs 逻辑回归 vs `SGDClassifier`，看效率和精度权衡。
